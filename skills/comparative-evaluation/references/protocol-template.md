# Comparison protocol

Fill this from inspected evidence and the assignment. Mark unknowns explicitly.
For protocol-only work, return it in conversation unless a saved artifact is
requested. Before trials, save the resolved protocol in authorized storage and
freeze its identity. Do not launch through unresolved execution or spending
permission.

## Question and decision

State what decision this comparison informs, its primary outcome, the smallest
useful effect, preserved behavior and hard failure conditions. Name the task
population and selected profiles: artifact quality, native activation/execution,
or end-to-end outcome. Explain what remains outside the claim.

## Contrast

Identify the baseline and each candidate, source revisions, exact instruction
and companion content, shared context and hashes. Explain whether this is an
as-used package comparison or a single-factor ablation. List every deliberate
difference, including models or tools when those are the treatment.

## Cases and evaluation

Name tasks and their independence groups. Distinguish development, validation
and untouched confirmation tasks, including prior exposure. Explain how each
case exercises the mechanism and which cases protect against regression.
Record the known-good, no-op and defective calibration outcomes with commands,
exit codes or graded evidence, including why each failure is intended.

Freeze primary measures, hard vetoes, executable acceptance and the qualitative
rubric. Name required real E2E journeys and resulting-state checks. For activation,
include both appropriate and inappropriate requests. Record human calibration
or explicitly label the absence of it.

## Execution and authority

Identify the actual executor and host, native integration, tool access and
versions. Record the observed-model verification method, snapshot-loading
checks, fresh-state procedure and permitted data access. Explain how evaluator
material and other trials are excluded, with any uncontrolled boundaries.

State tasks, repetitions per arm, total trials, ordering, concurrency, time
limits, retry classification, cancellation handling and stopping rule. Explain
the sizing rationale without treating repetitions as distinct tasks.

Record the caller's execution permission, resource limits or explicit approved
absence of a cap, permitted side effects, artifact destination and retention.
Estimate the finite pilot or study size when a further decision is needed.
Specify what stops execution or requires renewed approval.

## Grading and analysis

Name grader versions, independent judge contexts, anonymous output mapping,
presentation counterbalancing, and when unblinding occurs. Keep the treatment
key out of judge inputs and grading material out of target inputs.

Define matched comparisons, task clustering, missing/invalid-trial handling,
per-task reporting, uncertainty method or descriptive-only status, acceptance
gates and substantive verdict rules. State any equivalence margin before
results. Describe target/worker/user/retry/judge usage accounting and units,
separating setup time from trial execution when available.

## Evidence and completion

Define receipts for actual invocation, outputs, traces, independent acceptance,
failures, retries, model observations and resource usage. Preserve original
attempts and every round's immutable protocol and content identities.

Identify what compact non-sensitive evidence must survive temporary storage,
where it is authorized to persist, and how its readback will be checked.
Return execution status separately from the comparison verdict. List remaining
unverified profiles and human decisions without granting promotion authority.
