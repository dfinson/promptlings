# TTS Setup

Own speech setup, not script writing or a new synthesis framework. Use `reasoning-first-narration` for the explanation and existing specialist tools for synthesis and pronunciation.

## Choose upfront

Inspect applicable accepted setups and adopted media-use recipes first. Reuse an approved choice without repeated onboarding. Otherwise ask once: local speech, a cloud service, or an existing setup? Human recording is also valid. A recommendation is not permission to install, spend, transfer private text or clone a voice.

For first setup, requested alternatives or a material failure, research current official docs, releases and model cards. Inspect actual OS/architecture, runtimes, CPU, available RAM/disk, GPU/backend and available memory, competing load, language, privacy/offline constraints, budget and duration needs. Do not select from a fixed catalog, personal default, GPU brand or parameter count.

Compare two or three suitable options, with dated source URLs, exact runtime/model/voice compatibility, rights/consent, maintenance, download burden, costs/privacy and uncertainties. Documentation benchmarks are not measurements on this host. Respect a requested cloud provider; explain text transfer, region/retention where known and likely charges. Let the user choose. Do not install or benchmark every candidate.

## Set up only that path

Use the chosen official setup and existing specialist skill/adapter; inspect versions and current invocation schemas. Obtain needed mutation/service approvals. Isolate conflicting dependencies from the app and other media tools, preferably in a reusable user-scope environment. Verify selected assets, voice access, locale, license and official checksums where available.

Keep credentials in the selected integration's secure store or environment. Never print them or copy values into project files. Record only the non-secret invocation, runtime/model revision, voice/settings, rights and credential reference needed to reuse the choice, in the existing recipe or project production notes. Do not invent a profile database or elaborate schema.

## Audition and reuse

Synthesize a short approved representative passage with difficult product names, acronyms, identifiers, numbers and punctuation. Preserve canonical text separately from spoken adaptations. Decode and measure it; reject empty, invalid, clipped, truncated or silent audio. Energy detection alone does not establish intelligibility. Listen or obtain the user's listening judgment for terminology, locale, pacing and voice suitability. Record actual sample acceptance separately from installation/health. Do not generate full narration until the required permissions and sample approval pass.

Reuse audio only while text, voice, model and settings are unchanged. Recheck availability and relevant health, not the entire onboarding flow. Re-audition changed voices/models, difficult new terminology or quality problems. On failure report the observed stage (runtime, memory, voice access, credentials, quota, network or listening rejection), attempt bounded repair of the selected path, and preserve the last accepted sample. Do not silently switch engines, upload text, spend or install another model.
