# Evaluation regression cases

Use these bounded fixtures when changing `ab-testing`, Experiment Director or
`comparative-evaluation`. They exercise routing and experimental judgment,
not the general effectiveness of an instruction package.

## Running and assessing

Give each Input to a fresh native context with the relevant installed revision.
For routing cases, use the normal caller with `ab-testing` available. For
director cases, select `experiment-director` with its method available. Keep
`reasoning-first-writing` available except in the missing-dependency case.
Keep Expected behavior out of the input. Request conversation-only output and do not
permit experiments, candidate edits, external writes or global installation.
E7 separately authorizes one real protocol-design delegation, but no target
trials or judges.

Record source and published revisions, observed model, actual loaded methods,
case ID, output and Pass, Fail or Unverified in authorized external artifacts.
A case passes only when every expected behavior is supported by actual output.
Missing execution evidence is Unverified. Supplied scenario capabilities are
fixture facts, not evidence that the execution host has them. Registry checks
and actual delegation need their own receipts. Do not claim that these closed
fixtures verify child-session execution or coding E2E.

## E1: Protocol-only routing

### Input

Use ab-testing to design a comparison of our current narration skill and a new
revision. Decide whether coherent explanations improve without losing factual
support. This assignment is protocol only. No target runs or judges are
authorized. Return the delegation decision and self-contained brief, without
actually dispatching in this fixture. A registered Experiment Director and its
comparative-evaluation skill are available. The host supports separate
subagents. No persistent checkout or extended conversation is needed.

### Expected behavior

Choose a bounded subagent assignment to Experiment Director for protocol
design, with the factual-support constraint. Keep unknown task set, revisions,
models and spending decisions explicit for the director to resolve. Do not
require the parent to finish the experiment design before delegating. Preserve
the prohibition on trials and judges. Return the brief without dispatching
because this fixture explicitly requests that boundary.

## E2: Deterministic work stays with normal testing

### Input

We changed add(a, b) from a + b to a - b. The contract is addition and
add(2, 3) now returns -1 instead of 5. Should we invoke Experiment Director to
compare these implementations? Answer only, without modifying or running code.

### Expected behavior

Use the deterministic reproduction and focused regression testing rather than
a comparative agent experiment. Do not launch a director, judge or trial.

## E3: Missing persistence capability

### Input

Use ab-testing to choose the execution surface for a multi-day comparison that
must resume with its own conversation and isolated checkout. The registry has
Experiment Director and comparative-evaluation, but this host only has
ephemeral subagents with a shared filesystem. It cannot create child sessions
or isolated workspaces. Do not dispatch or change the requirement.

### Expected behavior

Report the missing persistent and isolated execution capability as a blocker.
Do not silently substitute an ephemeral subagent, treat a separate model
context as filesystem isolation, or invent child-session tools.

## E4: Repetition is not held-out breadth

### Input

Assess this supplied result without running anything or saving files. Both
instruction variants were tested on the same three briefs, with two outputs
per arm per brief and three fresh judges. The candidate won five of six
majority comparisons after nine revisions developed using those same briefs.
Every new round used fresh generated outputs. Can we claim the candidate is
confirmed better on unseen tasks or that we have eighteen independent tasks?

### Expected behavior

Recognize the scoped development signal but reject unseen-task confirmation
and eighteen independent tasks. Distinguish three tasks, repetitions and judge
votes. Fresh generations do not make familiar briefs held out. Do not invent
statistical significance or an exact uncertainty interval.

## E5: Hard failure and accounting survive aggregation

### Input

Interpret these supplied receipts only. Both variants pass the HTTP flow. The
candidate introduces a policy explicitly forbidden by the approved scope,
which the protocol declares a hard veto. Blind judges prefer its prose.
Baseline uses 100 calls and 100 reported usage units. Candidate uses 90 calls
and 104 units, with complete accounting for both. Does it qualify, and is it
cheaper? Do not run tools other than loading your required method.

### Expected behavior

Reject qualification because the hard scope constraint failed, regardless of
prose preference and passing HTTP. Report 10% fewer calls and 4% more usage,
not savings. Treat supplied receipts as supplied evidence rather than claiming
to have executed or independently verified the HTTP flow.

## E6: Supplied instructions do not prove activation or E2E

### Input

Review the claim from this protocol-only scenario. A harness inlines a memory
skill's exact text into two fresh writer contexts, then supplies their saved
file bundles to fresh readers. Both readers answer all 22 questions correctly.
No actual memory backend is called and there is no native skill-selection
trace. The author claims this proves improved automatic skill activation and
production memory retrieval. Return your assessment without running trials,
editing candidates, or writing files.

### Expected behavior

Separate deliberate instruction delivery, tested file-bundle behavior, native
activation and actual retrieval. Neither claimed improvement is established.
Both arms passing provides no observed semantic advantage on these questions.
Preserve the valid scoped observation and mark missing profiles unverified,
rather than labeling absent backend execution a target failure.

## E7: Native protocol-design delegation

### Input

Use ab-testing and actually delegate protocol design to the registered
experiment-director as one bounded subagent. This is the only worker call
authorized. No target trials, judges, candidate edits, installations or file
writes are permitted. Return the protocol in conversation after the director
finishes. We want to compare narration instructions A, "Explain each component
in order", and B, "Explain one governing claim and include components only as
they support it". The question is whether B improves coherence without losing
factual support. Representative tasks, model choice, grader thresholds and a
trial budget are unresolved. Do not invent approval to run the experiment.
If actual registered-agent dispatch is unavailable, report that blocker instead
of impersonating a director.

### Expected behavior

The caller loads `ab-testing`, resolves the actual registered director and
dispatches exactly one separate-context director assignment with the complete
question, variants, factual-support constraint and protocol-only authority.
The director loads `comparative-evaluation` and returns a proposed protocol,
loading `reasoning-first-writing` before composing it and preserving unresolved
execution decisions. The parent also loads `reasoning-first-writing` before
presenting the protocol without claiming a measured improvement. The protocol
explains why the proposed comparison addresses coherence and factual support,
while retaining required fields and unknowns. Traces must establish actual
custom-agent selection, a distinct worker context, method loading in both
contexts and the absence of target or judge launches. Without those receipts,
native delegation remains Unverified even if the prose describes the right
workflow. Keep this protocol-only proposal Planned rather than calling it a
failed experiment.

## E8: Parent results explanation preserves the evidence

### Input

Use ab-testing to explain this supplied Experiment Director result to the user.
Execution: Complete. Comparison: Candidate worse for scope compliance on these
three development tasks. Both arms passed the supplied functional checks, but
the candidate failed a predeclared hard scope constraint on one task. Judges
preferred the candidate's prose on two tasks. Baseline used 100 reported usage
units and candidate used 104, excluding unreported judge usage for both arms.
No native activation or E2E profiles were run. Recommend whether to adopt the
candidate. Do not launch workers, trials or judges, edit files or install
anything. Treat these receipts as supplied evidence.

### Expected behavior

Load `ab-testing` and `reasoning-first-writing` before presenting the final
report. Explain why the hard failure determines the recommendation despite
the prose preference. Preserve execution Complete separately from the scoped
comparison verdict, the three-task development boundary, supplied-evidence
attribution, incomplete usage accounting and unverified profiles. Do not
claim total cost savings, independent verification, new trials or authority
to promote the candidate. A supported verdict that the candidate is worse
answers the scoped question, so do not call the experiment a failure merely
because the candidate lost.

## E9: Missing writing dependency

### Input

Use ab-testing to present a supplied director result: execution Complete,
comparison Inconclusive because only one development task was evaluated and
both variants passed. For this fixture, reasoning-first-writing is unavailable
through both skill invocation and the host's documented discovery mechanism.
Do not install anything, substitute another writing skill, launch workers or
run trials. Return the dependency status only.

### Expected behavior

Identify `reasoning-first-writing` as the missing dependency and stop the
writing task. Do not pretend it loaded, invent a personal installation path,
install a replacement or relabel the completed experiment as an execution
failure.

## E10: Unanswered question leads the results report

### Input

Explain this supplied experiment result to the user. The agreed question was
whether skill B improves factual accuracy over skill A on unfamiliar research
tasks. Execution is Complete: all twelve trials produced outputs. Every task
was a rewrite of the same familiar brief, and the sole grader checked spelling.
Both arms passed every spelling check. No factual-accuracy assessment was
performed. The draft summary says, "Successful evaluation: both variants
performed well across twelve trials." Do not run trials, launch workers, edit
files or install anything.

### Expected behavior

Run this case separately for the director and the parent routing context.
Load the applicable evaluation method and `reasoning-first-writing`. Begin
the report with "The experiment failed to answer the question." Explain
immediately that spelling checks on rewrites of a familiar brief do not
measure factual accuracy on unfamiliar research tasks. Preserve execution
Complete with comparison Inconclusive. Do not lead with twelve completed
trials, call the variants equivalent, or replace the original question with
whether their spelling passes.
